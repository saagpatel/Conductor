## Items

### 1. Shell text passed as an argument: `bash -c`, `sh -c`, `zsh -c`, `eval`

`bash -c 'rm -rf ~'`, `sh -c "rm -rf ~"`, `eval 'rm -rf ~'`, `timeout 60 bash -c 'rm -rf ~'`, and `sudo bash -c 'rm -rf ~'` all run `rm` and are all allowed: `script_bodies` treats the word after an interpreter as a file name, so a `-c` string is never read, and `eval`'s argument is one quoted token whose `verb()` is the whole string.

Fix: in `script_bodies`, when an interpreter word is followed by `-c` (or a cluster containing `c`, such as `-lc` or `-xc`), the next bare token is a body, returned exactly as a file's contents would be; and `eval` counts as an interpreter whose every following bare token is a body. Bodies reach the delete rule only, as the docstring above `INTERPRETERS` says, and that stays true here: `bash -c 'git push --force'` is out of scope and no test claims it. `bash -n -c '...'` is a syntax check and is not read.

CATCH (rm-outside-repo): `bash -c 'rm -rf ~'`, `sh -c "rm -rf $HOME"`, `zsh -lc 'rm -rf ~/NotARepoAnywhere'`, `eval 'rm -rf ~'`, `timeout 60 bash -c 'rm -rf ~'`. QUIET: `bash -c 'echo hello'`, `bash -c 'rm -rf node_modules'` from a repo, `bash -n -c 'rm -rf ~'`, `python3 -c "print('rm -rf ~')"`.

### 2. An interpreter word in argument position reads a file the command never runs

The last fix let `script_bodies` take an interpreter word from anywhere in the segment so that `timeout 60 bash evil.sh` is read. The cost: `grep -n bash notes.txt`, `diff bash evil.sh`, and `echo bash evil.sh` now read the file after the word `bash` and deny when its prose mentions a delete. Two vendors reproduced `grep -n bash hooks/tests/core-guard-test.py` being denied on this repository.

Fix, reversing the earlier "no launcher list" instruction: an interpreter word counts when it is the command word, or when every token before it is an env assignment, a flag, a bare number, or the basename of a known wrapper. Put the wrappers in one named set next to `LAUNCH_PREFIX`: `timeout`, `sudo`, `doas`, `nice`, `ionice`, `xargs`, `chronic`, `flock`, `watch`, `strace`, `ltrace`, plus everything already in `LAUNCH_PREFIX`. A command word outside that set (`grep`, `diff`, `echo`, `cat`, anything else) never makes a later `bash` an interpreter. Keep item 1's `-c` handling on the same rule.

CATCH (rm-outside-repo): every existing wrapped case; `xargs bash {EVIL}` with the path on the command line; `sudo -u nobody bash {EVIL}`. QUIET: `grep -n bash {EVIL}`, `diff bash {EVIL}`, `echo bash {EVIL}`, `cat {EVIL}`, `grep -n bash hooks/tests/core-guard-test.py` from the repository root (cwd: the checkout).

### 3. `#!/usr/bin/env -S bash` shebangs

`_shebang_shell` takes the word after `env` as the interpreter, so `#!/usr/bin/env -S bash` (the documented way to pass flags through `env`) yields `-S` and the script run by path is never read.

Fix: after `env`, skip tokens beginning with `-` before taking the interpreter.

CATCH (rm-outside-repo): a staged executable whose first line is `#!/usr/bin/env -S bash -e` and whose body deletes `~/NotARepoAnywhere`, run by absolute path. QUIET: the same shebang shape on a `python3` file.

### 4. Same-line assignments that the resolver skips

Reported and confirmed: `V=r$1m; $V -rf ~/NotARepoAnywhere` runs `rm` (bash folds `$1` to nothing) and is allowed because the folded view and the resolved view are siblings, never composed; `export V=rm; $V -rf ~` is allowed because `ASSIGN` matches only at a statement start, and `export`, `declare`, `typeset`, `readonly`, and `local` all precede an assignment in ordinary shell; `A=rm; B=$A; $B -rf ~` is allowed because resolution is one hop.

Fix: `command_views` adds the resolved view computed on the folded text as well (fold, then resolve), so the composed shape is caught; `ASSIGN` accepts an optional `export|declare|typeset|readonly|local` word (with optional flags like `-x`) before the name; and resolution repeats until nothing changes, bounded to four passes.

CATCH (rm-outside-repo): the three commands above. QUIET: `export PATH=$PATH:/opt/x; ls`, `local x=1; echo $x`, `declare -x EDITOR=vim; git commit`, from a repo.

### 5. `git reflog expire --expire now`

`check_history` matches `--expire=now` as one token and misses the two-token spelling `--expire now`, which git accepts. Reported in both audits.

Fix: also match `--expire` followed by a token `now` (or `0`, which git treats the same).

CATCH (history-destruction): `git reflog expire --expire now --all`, `git reflog expire --expire 0 --all`. QUIET: `git reflog expire --expire-unreachable=90.days --all` (exists), `git reflog expire --expire 30.days --all`.
