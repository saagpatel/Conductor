# The September reset: what the receipts say about pipeline shape

Written 2026-09-04 after the operator paused feature work at v0.12.0. Five releases shipped
through one pipeline shape (Sol builds, Opus reviews cold, Sol fixes on a resumed thread) at
$13 to $19 each. That shape was a habit. This note replaces it with measurements, records what
the research pass found, and sets the post-reset order. Sources: `docs/research/2026-09-04-*.md`.

reliability. The open-models report lists the documented long-horizon failures per model.

## 2. What the reviewer research changes

- Our review prompts said "hunt for defects" and used a `DEFECT:` prefix. Framing research shows
  that inflates findings; the inverse ("be conservative") makes Opus 5 and Sonnet 5 silently
  drop real bugs; demanding a fix per finding made judges reject correct code three times as
  often. No study measures a fixed count directly, but a count is a documented manipulation
  lever in both directions.
- New rule set in `AGENTS.md` ("Reviewer prompts: no quotas, ever"): consequence threshold,
  explicit permission for an empty result, confidence and citation per item, find and filter as
  separate stages, whole review in the final message, swapped-order judging, no self-vendor
  judging, quorum is a gate not a proof.
- Conductor's verdict checklist (A2) is already the filter stage. The change is to the finding
  prompt in front of it, and to A3/A4 (judge hygiene) which the research now justifies with
  citations rather than instinct.

| fix, Sonnet 5 standard, `test_policy: allow` | reproduced both, fixed both, one new test; gate green | $0.57 | 3 min |

| **total** | ok | **$19.65** | |

Against $19.40 for v0.12.0 on Sol/Opus, so no saving this time, and the whole gap is operating error,
not lane capability: the work that shipped cost $8.90 (the resumed build plus review, fix, lead).

- **Size the build cap to the spec.** A seven-item spec on Sonnet at high effort spends $6 to $7; a $3
  cap bought two partial builds. Rule: about a dollar per spec item for the build lane.
- **A spec that changes what existing missions are permitted to do needs `test_policy: allow` on its
  build lane.** The clean policy (A1) reruns the original tests against the new source; when the new
  source refuses shapes the old tests build, that failure is the feature working. Both builders were
  right and both were rejected. The lead reads every existing-test edit in that case, which is what
  happened here: each edit carried a written reason, none weakened an assertion.
- **The salvage path works.** A build lane's kept worktree with a green own gate is a deliverable; a
  review-and-fix mission runs on it with `cwd` set to the worktree and the diff pasted into the
  mission prompt. Cost of the remainder: $1.50.
- **Grok earned its lane again:** the spend-attribution bug is exactly the kind of cross-module
  consequence a builder misses and a cold reader catches. Gemini's NO_FINDINGS was also correct on
  the items it could see; the bug was outside the diff.
